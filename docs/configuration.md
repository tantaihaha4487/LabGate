# Configuration

Run `sudo labgate setup --server` for guided server configuration. It preserves existing secrets and key material and writes `/etc/labgate/server.json` atomically. It never prepares a database. Configuration and private keys must remain private; do not commit them.

The default server listens on `127.0.0.1:3000`. Put your approved HTTPS reverse proxy or Tailscale Funnel in front of it. Set the exact public origin in the wizard, without a trailing slash. For a Tailscale-only HTTP machine origin, use the canonical origin supported by the machine installer; remote admin clients require HTTPS.

In Google Cloud, use a Web application OAuth client and register:

```text
https://YOUR-SERVER/api/auth/callback/google
```

The server uses verified OpenID Connect, institutional `hd` and email claims, state, nonce, and PKCE. The client secret stays on the server; admin computers never need it. Existing Google client credentials may be reused when their callback origin matches. Provider access/refresh tokens are not retained.

The JSON fields map to the former configuration as follows:

| Former variable | JSON field |
| --- | --- |
| `BETTER_AUTH_URL` | `origin` |
| `GOOGLE_CLIENT_ID` | `googleClientId` |
| `GOOGLE_CLIENT_SECRET` | `googleClientSecret` |
| `ALLOWED_EMAIL_DOMAIN` | `allowedEmailDomain` |
| `ADMIN_EMAILS` | `adminEmails` (array) |
| `DATABASE_URL=file:...` | `database` (filesystem path) |
| `PROVISIONER_SSH_KEY_PATH` | `provisionerKey` (absolute path) |
| `CREDENTIAL_TTL_HOURS` | `credentialTTLMinutes` (hours × 60) |
| `GUEST_PASSWORD_LENGTH` | `passwordLength` |
| `MACHINE_REGISTRATION_SECRET` | `registrationSecret` |
| `CRON_SECRET` | `cronSecret` |

Better Auth’s secret is retired because the new system uses opaque, randomly generated session credentials whose hashes are stored in SQLite. Browser and CLI sessions expire after seven days and are independently revoked on logout.

The installer creates `/etc/labgate/provisioner_key.pub`; give this non-secret public key to the machine installer. During conversion, retain the existing private key and registration secret to avoid unnecessary re-enrollment. To use existing material, prepare the JSON with those paths/values before rerunning setup. Do not transmit private keys or bearer secrets through logs or shell arguments.

An administrator configuration line generated by the web/TUI interface is a preview, not a permission change. Apply the corresponding email list through server setup, then restart `labgate.service`. Domain and privilege checks apply on each request, so removing an administrator prevents subsequent admin operations even with an unexpired session.

For a nondefault configuration path, set `LABGATE_CONFIG` or pass `--config` to server/setup/check and the standalone migration executable. Custom database directories must be writable by the service account; adjust the systemd `ReadWritePaths` for a nondefault location. The setup wizard never guesses ownership or moves an existing database.
